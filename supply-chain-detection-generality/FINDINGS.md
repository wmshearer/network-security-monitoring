README.md), not a summary report. Every number below cites the script,
evidence JSON, or corpus file it comes from.

### The 23 behavioral detections

18 are GitHub Enterprise/Organizations audit-log detections that match a
platform-defined API action name (for example
`action=repository_vulnerability_alerts.disable`), not an attacker-chosen
string; see `rubric/RUBRIC.md`'s "platform-vocabulary exception" for why
these are not treated the same as SUNBURST's hardcoded DLL name despite both
looking like literal string matches. The remaining 5 are
`github_workflow_file_creation_or_modification.yml` (matches any workflow
file under `.github/workflows/`, not a specific name) and four
package-installation-mechanism detections
(`python_network_traffic_during_package_build.yml`,
`python_pth_file_creation_during_package_installation.yml`,
`python_pythonpath_modification_during_package_installation.yml`,
`python_site_hooks_creation_during_package_installation.yml`), which match
generic Python packaging mechanics (`build_wheel`, `.pth` file creation,
`PYTHONPATH` modification, `sitecustomize.py`) rather than any one
incident's file names. Full list and per-file reasoning: `rubric/calls.csv`.

## 5. SUNBURST's technique tag is wrong or at least inconsistent with the rest of the corpus

- Direct read of `detections/endpoint/sunburst_correlation_dll_and_network_event.yml`
  shows `mitre_attack_id: [T1203]` only. T1203 is "Exploitation for Client
  Execution" per `attack.mitre.org/techniques/T1203/` (page title confirmed
  live). T1195 ("Supply Chain Compromise") does not appear anywhere in this
  file's tags, despite the detection existing specifically to catch the
  SUNBURST supply chain campaign and being filed under the `NOBELIUM Group`
  analytic story.
- Practical effect: **a search for T1195-tagged content in this repository
  misses the one detection built for the most famous supply chain attack in
  the dataset.** Confirmed by `tests/test_ground_truth.py::test_sunburst_is_tagged_t1203_not_t1195`.

## 10. Splunk Web GUI evidence: attempted, session expired mid-task, disclosed rather than faked

Full sequence in `evidence/gui/README.md`. Summary: Splunk was running and
authenticated at the start of this task; ingesting the real Sysmon XML
telemetry required a `props.conf` line-breaking fix; applying it required a
`splunk restart`; the restart invalidated the authenticated session; the
admin password is intentionally not stored anywhere retrievable (see the
director's memory file on why); re-authentication was not possible. No
Splunk Web screenshot was captured or fabricated. The `props.conf` change
was reverted. A handful of malformed test events remain in the lab's
`ingest_lab` index under clearly project-tagged sources
(`scd_project_shai_hulud_v2/v3`, `scd_project_3cx_v2/v3`); they could not be
deleted because the available session lacked delete privileges, and this is
disclosed rather than hidden.

## 11. Scope boundary: what was excluded from the 29, and why

A looser search for any detection whose `analytic_story` mentions "Supply
Chain" anywhere (not just a T1195 tag) pulls in dozens of unrelated,
general-purpose detections: Azure AD / O365 service-principal and
permission-grant detections, generic Windows persistence and
living-off-the-land detections, `tor_traffic.yml`, and others that list
"Supply Chain Compromise" or "3CX Supply Chain Attack" as one of several
analytic stories they are filed under, without being specific to supply
chain compromise as a technique. That full list (over 70 files matching the
loose search, well beyond the 29 in the core population) was generated
during scoping but deliberately not classified, because most of those
detections' supply-chain relevance is incidental to the story-tag system,
not to their actual search logic. Scoping to the 28 T1195-tagged files plus
SUNBURST keeps every classified row's relevance to the research question
unambiguous without a second layer of judgment calls about "is this
detection really about supply chain compromise."

Also excluded: `detections/cloud/circle_ci_disable_security_job.yml`,
`detections/cloud/circle_ci_disable_security_step.yml` (tagged `T1554` only,
not `T1195`), `detections/cloud/microsoft_intune_*.yml` (tagged `T1072`
only), and `detections/endpoint/detection_of_tools_built_by_nirsoft.yml`
(tagged `T1072` only). These are adjacent techniques (persistence via
compromised binaries, software deployment tooling) that can appear in a
supply chain compromise but are not themselves tagged as Supply Chain
Compromise.
